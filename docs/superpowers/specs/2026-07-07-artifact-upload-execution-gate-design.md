# Artifact Upload Execution Gate Design

## Goal

Add a local read-only artifact upload execution gate after a green tag creation execution gate.

The gate validates that artifact upload has enough structured review evidence before any real upload command can be considered. It does not create artifacts, compute checksums, upload files, create releases, deploy, call external connectors, write stores, use credentials, or claim production readiness.

## In Scope

- Add an artifact upload execution gate checker.
- Read one local artifact upload gate JSON file.
- Reuse the tag creation gate checker.
- Require the referenced tag creation gate report to be green, gate-only, non-publishing, and non-production.
- Require artifact upload gate identity fields:
  - gate id;
  - tag creation gate path;
  - owner;
  - recorded time;
  - target version;
  - release action.
- Require artifact upload request metadata:
  - artifact name;
  - artifact type;
  - source artifact path;
  - upload destination;
  - upload command;
  - upload path policy.
- Require artifact identity review metadata:
  - artifact name matches target version;
  - artifact type reviewed;
  - source path scoped to release artifact output;
  - destination reviewed;
  - release tag linkage reviewed.
- Require checksum and provenance policy metadata:
  - checksum required;
  - checksum algorithm declared;
  - checksum not generated by this gate;
  - provenance required;
  - provenance not generated by this gate.
- Require ordered command evidence for tag creation gate, release hygiene, controlled-runtime, core workflows, lint, build, and `git diff --check`.
- Require rollback plan, monitoring plan, credential boundary, artifact upload decision, and artifact upload boundary sections.
- Require artifact upload decision to remain blocked until a future operator execution approval.
- Require the artifact upload boundary to prove gate-only behavior with no artifact creation, no checksum creation, no upload, no release creation, no deployment, no external writes, no store writes, no credential use, no production readiness, and no production-readiness claim.
- Add an npm script, tracked example gate JSON, tests, docs, and memory updates.

## Out of Scope

- Run upload commands such as `gh release upload`, `scp`, `rsync`, cloud CLIs, or connector uploads.
- Create, write, hash, move, or upload package artifacts.
- Create release records.
- Deploy to any environment.
- Call external connectors or use credentials.
- Mutate playbooks, fixtures, stores, business assets, or release evidence.
- Publish a release.
- Claim production readiness.
- Replace future artifact upload execution approval, deployment, monitoring, incident, or rollback execution gates.

## Contract

Input gate JSON:

- `gateId`
- `tagCreationGatePath`
- `owner`
- `recordedAt`
- `targetVersion`
- `releaseAction: "artifact_upload"`
- `tagCreationGateResult`
- `artifactUploadRequest`
- `artifactIdentityReview`
- `checksumProvenancePolicy`
- `commandEvidence`
- `rollbackPlan`
- `monitoringPlan`
- `credentialBoundary`
- `artifactUploadDecision`
- `artifactUploadBoundary`
- `approvalStatus: "artifact_upload_execution_gate_review"`
- `notes`

Output report:

- `ok`
- `command: "release:artifact-upload:gate:check"`
- `productionReady: false`
- `publishingPerformed: false`
- `gateOnly: true`
- `readyForArtifactUploadOperatorReview`
- `artifactUploadGateClaim: "artifact_upload_execution_gate_defined"` only when green
- `status`
- `checks`
- `findings`
- `nextCommand`
- `nextAction`

## Acceptance Criteria

- A valid artifact upload gate referencing the tracked tag creation gate passes.
- The gate fails if the referenced tag creation gate report is not green, gate-only, non-publishing, or non-production.
- The gate fails if identity fields, owner, target version, or release action are missing or malformed.
- The gate fails if artifact upload request metadata is missing or does not match the target version.
- The gate fails if artifact identity review metadata is missing.
- The gate fails if checksum / provenance policy metadata is missing or records generated checksum/provenance by this gate.
- The gate fails if command evidence entries are missing, out of order, non-green, or missing required metadata.
- The gate fails if rollback plan, monitoring plan, credential boundary, or artifact upload boundary are missing.
- The gate fails if artifact upload decision approves execution, records upload, allows release creation, or allows credential use.
- The gate fails if artifact upload boundary records generated artifacts, generated checksums, uploaded artifacts, release creation, deployment, external writes, store writes, credential use, production readiness, or readiness claim.
- The CLI returns exit code `0` for valid gates and `1` for invalid gates.

## Next Boundary

After this gate is green, the next separate phase can design the deployment execution gate. Artifact upload itself still remains blocked until a future explicit operator execution approval and artifact verification gate exist.
